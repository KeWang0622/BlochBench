# How large agent and science benchmarks are built and run: a primary-source survey for BlochBench

> Historical development note (1 November 2026). For current release status and evidence, use
> [the datasheet](../DATASHEET.md), [offline results](OFFLINE-RESULTS.md) and [roadmap](ROADMAP.md).

Accessed: 2026-11-01. Every claim below comes from a page opened during this session; the URL sits next to the claim. Wording is paraphrased unless shown in quotation marks. Source dates are given where the page states one. Items I could not confirm are listed in section (d) and were left out of the analysis.

BlochBench context: 24 task families, 88 instances, about 6.7 GB of task data, graders that need Python 3.12 plus Julia/KomaMRI in Docker, a public split with planned semi-private and private splits, hosted on AWS.

## (b) Practices that recur

1. **One container image per task or environment, prebuilt and pulled from a registry.** SWE-bench builds base/env/instance layers and can pull prebuilt images ([harness](https://github.com/SWE-bench/SWE-bench/blob/main/docs/reference/harness.md)); Epoch mirrors them on GHCR ([repo](https://github.com/epoch-research/SWE-bench)); Harbor tasks may name a prebuilt image ([guide](https://github.com/harbor-framework/docs/blob/main/guides/creating-tasks.mdx)); BixBench ships a Docker image ([repo](https://github.com/Future-House/BixBench)).
2. **A declarative task directory: instruction, environment, verifier, reference solution, resource and timeout config.** Harbor ([guide](https://github.com/harbor-framework/docs/blob/main/guides/creating-tasks.mdx)), METR Task Standard ([repo](https://github.com/METR/task-standard)), Inspect `@task` ([docs](https://inspect.aisi.org.uk/tasks.html)), inspect_evals `eval.yaml` ([CONTRIBUTING](https://github.com/UKGovernmentBEIS/inspect_evals/blob/main/CONTRIBUTING.md)).
3. **Verifier separated from the agent, with no network.** TB-Science verifier runs in a separate no-network environment and receives declared artifacts ([template](https://github.com/harbor-framework/terminal-bench-science/blob/main/task-template.toml)); Inspect sandboxes default to no network ([docs](https://inspect.aisi.org.uk/sandboxing.html)); Epoch cuts git history and network ([page](https://epoch.ai/benchmarks/swe-bench-verified)). Terminal-Bench removed a submission that copied each task's `tests/` into agent setup ([integrity](https://www.tbench.ai/news/leaderboard-integrity-update)).
4. **Oracle and null-agent checks before release.** Harbor tests the verifier against the reference solution ([guide](https://github.com/harbor-framework/docs/blob/main/guides/creating-tasks.mdx)); TB-Science asks users to run oracle solutions five times ([repo](https://github.com/harbor-framework/terminal-bench-science)); Terminal-Bench quality checks include oracle and no-op agents ([continuous](https://www.tbench.ai/news/continuous-benchmarks)); ABC shows a do-nothing agent scoring 38% on tau-bench Airline ([ABC](https://arxiv.org/html/2507.02825)).
5. **Hidden answers or hidden tasks, graded by the maintainer.** GAIA ([dataset](https://huggingface.co/datasets/gaia-benchmark/GAIA)), SWE-bench Multimodal test ([datasets guide](https://github.com/SWE-bench/SWE-bench/blob/main/docs/guides/datasets.md)), LAB-Bench 20% private ([repo](https://github.com/Future-House/LAB-Bench)), HLE held-out ([paper](https://arxiv.org/html/2501.14249)), SWE-Bench Pro held-out and commercial ([paper](https://arxiv.org/abs/2509.16941)), ARC semi-private and private ([policy](https://arcprize.org/policy)).
6. **Tiered secrecy matched to who runs the model.** ARC uses the semi-private set for API models under zero-data-retention terms and the private set only offline on Kaggle with no internet ([policy](https://arcprize.org/policy), [2026](https://arcprize.org/competitions/2026)).
7. **Hosted evaluation behind authenticated keys and quotas.** sb-cli: email-verified API key, quotas per subset and split, runs on AWS ([auth](https://www.swebench.com/sb-cli/authentication/), [quotas](https://www.swebench.com/sb-cli/user-guide/get-quotas/), [harness](https://github.com/SWE-bench/SWE-bench/blob/main/docs/reference/harness.md)); EvalAI auth token plus queue ([docs](https://evalai.readthedocs.io/en/latest/02-for-challenge-hosts/evaluation/remote-evaluation.html)); GAIA Space ([Space](https://huggingface.co/spaces/gaia-benchmark/leaderboard)).
8. **Maintainers rerun or reproduce before a result counts as verified.** OSWorld-Verified runs submitted agent code ([blog](https://xlang.ai/blog/osworld-verified)); ARC reproduces via Kaggle notebook ([policy](https://arcprize.org/policy)); TB 4.0 accepts only maintainer-run results ([SUBMIT.md](https://github.com/harbor-framework/terminal-bench/blob/main/leaderboard/SUBMIT.md)); MLE-bench paused submissions to design a fair process ([repo](https://github.com/openai/mle-bench)).
9. **Submissions must include full trajectories and logs, checked by CI and a judge.** SWE-bench experiments plus `submit verify` ([repo](https://github.com/SWE-bench/experiments)); Terminal-Bench ATIF trajectories, CI checks and trajectory judge ([SUBMIT.md](https://github.com/harbor-framework/terminal-bench/blob/main/leaderboard/SUBMIT.md), [ATIF](https://github.com/harbor-framework/harbor/blob/main/rfcs/0001-trajectory-format.md)); HAL LLM-assisted log inspection ([paper](https://arxiv.org/abs/2510.11977)).
10. **Fixed run settings and repeated trials, with failures counted.** Terminal-Bench: at least 5 trials, no overrides, errors score 0 ([SUBMIT.md](https://github.com/harbor-framework/terminal-bench/blob/main/leaderboard/SUBMIT.md)); MLE-bench: at least 3 seeds, mean plus/minus SE ([repo](https://github.com/openai/mle-bench)); TB-Science: 3 trials per task ([post](https://www.tbench.ai/news/terminal-bench-science-0-1)); ARC: single run with cost cap ([policy](https://arcprize.org/policy)).
11. **Cost and tokens reported next to accuracy.** HAL ([paper](https://arxiv.org/abs/2510.11977), [harness](https://github.com/princeton-pli/hal-harness)); Terminal-Bench leaderboard columns for cost and tokens ([leaderboard](https://www.tbench.ai/leaderboard/terminal-bench/2.0)); ScienceAgentBench cost metric ([paper](https://arxiv.org/abs/2410.05080)); PaperBench judge cost ([HTML](https://arxiv.org/html/2504.01848)); Epoch token limits ([page](https://epoch.ai/benchmarks/swe-bench-verified)).
12. **Machine-detectable markers and encryption against training contamination.** BIG-bench canary GUID ([README](https://github.com/google/BIG-bench/blob/main/bigbench/benchmark_tasks/training_on_test_set/README.md)), reused by LAB-Bench ([repo](https://github.com/Future-House/LAB-Bench)) and Harbor's TB-Science template ([template](https://github.com/harbor-framework/terminal-bench-science/blob/main/task-template.toml)); BrowseComp decrypts fields using the canary as password ([code](https://github.com/openai/simple-evals/blob/main/browsecomp_eval.py)); CORE-Bench gpg test set ([repo](https://github.com/siegelz/core-bench)); ScienceAgentBench password zip ([repo](https://github.com/OSU-NLP-Group/ScienceAgentBench)); HAL encrypted traces ([harness](https://github.com/princeton-pli/hal-harness)); GAIA no-reshare terms ([dataset](https://huggingface.co/datasets/gaia-benchmark/GAIA)).
13. **Time-based refresh and versioned releases.** LiveBench ([paper](https://arxiv.org/html/2406.19314)), LiveCodeBench ([paper](https://arxiv.org/html/2403.07974)), Terminal-Bench patch/minor/major scheme with regrading of saved artifacts ([continuous](https://www.tbench.ai/news/continuous-benchmarks)), Epoch changelogs ([page](https://epoch.ai/benchmarks/swe-bench-verified)), inspect_evals task version bumps ([CONTRIBUTING](https://github.com/UKGovernmentBEIS/inspect_evals/blob/main/CONTRIBUTING.md)).
14. **Explicit anti-cheating rules.** PaperBench URL blacklist and monitor ([HTML](https://arxiv.org/html/2504.01848)); MLE-bench plagiarism check ([paper](https://arxiv.org/html/2410.07095)); SWE-bench bans hints and test knowledge ([checklist](https://github.com/swe-bench/experiments/blob/main/checklist.md)); Terminal-Bench zeroes reward-hacked trials ([integrity](https://www.tbench.ai/news/leaderboard-integrity-update)).
15. **Expert validation of every task before release.** SWE-bench Verified ([OpenAI](https://openai.com/index/introducing-swe-bench-verified/)), ScienceAgentBench nine experts ([paper](https://arxiv.org/abs/2410.05080)), TB-Science 70 of 920 proposals accepted after review ([post](https://www.tbench.ai/news/terminal-bench-science-0-1)), PaperBench rubrics with paper authors ([paper](https://arxiv.org/abs/2504.01848)), OSWorld-Verified fixes ([blog](https://xlang.ai/blog/osworld-verified)).
16. **Graders that accept equivalent answers and give partial credit; LLM judges are themselves evaluated.** OSWorld-Verified tolerant evaluators ([blog](https://xlang.ai/blog/osworld-verified)); Harbor fractional and JSON rewards ([guide](https://github.com/harbor-framework/docs/blob/main/guides/creating-tasks.mdx)); PaperBench JudgeEval ([HTML](https://arxiv.org/html/2504.01848)); SciCode stored numeric results ([repo](https://github.com/scicode-bench/SciCode)).
17. **Parallel cloud execution.** HAL on hundreds of Azure VMs ([paper](https://arxiv.org/abs/2510.11977)); OSWorld on AWS, 50 parallel environments ([blog](https://xlang.ai/blog/osworld-verified)); Harbor cloud providers ([README](https://github.com/harbor-framework/harbor)); Inspect K8s and EC2 sandboxes ([k8s](https://k8s-sandbox.aisi.org.uk/), [EC2](https://github.com/UKGovernmentBEIS/inspect_ec2_sandbox)); SWE-bench on Modal or AWS ([eval guide](https://github.com/SWE-bench/SWE-bench/blob/main/docs/guides/evaluation.md)).
18. **Machine-readable dataset documentation required by venues.** NeurIPS 2026 Evaluations & Datasets track requires a validated Croissant file with core and Responsible AI fields, reviewer access without request, a small sample if over 4 GB ([CFP](https://neurips.cc/Conferences/2026/CallForEvaluationsDatasets), [hosting](https://neurips.cc/Conferences/2026/EvaluationsDatasetsHosting)); Croissant 1.1 recommends SHA-256 checksums for versioned datasets ([spec](https://docs.mlcommons.org/croissant/docs/croissant-spec-1.1.html)); RAI vocabulary ([RAI spec](https://docs.mlcommons.org/croissant/docs/croissant-rai-spec.html)); Datasheets ([paper](https://arxiv.org/abs/1803.09010)).
19. **Published quality checklists, reporting rules and retirement plans.** ABC: task validity, outcome validity, reporting ([paper](https://arxiv.org/abs/2507.02825)); BetterBench: 46 practices, lifecycle from design to retirement ([paper](https://arxiv.org/abs/2411.12990), [HTML](https://arxiv.org/html/2411.12990)); OpenAI retiring SWE-bench Verified ([post](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/)); METR deprecating its public tasks ([repo](https://github.com/METR/public-tasks)).

## (c) Recommendations for BlochBench

Tags: **[AWS]** needs cloud infrastructure; **[Docs/process]** is documentation, policy or review work; **[CI]** is automation that can run on GitHub Actions or AWS. Numbers in brackets refer to the practices above.

1. **Adopt a Harbor-style task directory (2).** For each of the 88 instances: `tasks/<family>/<instance>/task.toml`, `instruction.md`, `environment/Dockerfile` (or a pinned image reference), `tests/` (grader entry point writing `/logs/verifier/reward.json` with sub-scores), `solution/solve.sh`, `README.md` with the scientific rationale. Add a thin Inspect `@task` wrapper so Inspect users (Epoch, METR, inspect_evals) can run it. [Docs/process]
2. **Build two pinned images (1).** `mrab-agent` (Python 3.12 plus task tooling) and `mrab-grader` (Python 3.12, Julia, KomaMRI with packages precompiled; KomaMRI is MIT-licensed, [repo](https://github.com/JuliaHealth/KomaMRI.jl)). Reference them by digest in `task.toml`. Public-split images go to Amazon ECR Public, which allows anonymous pulls ([docs](https://docs.aws.amazon.com/AmazonECR/latest/public/what-is-ecr.html)); hidden-split grader images go to a private registry. [AWS]
3. **Keep the 6.7 GB of data outside the images (1, 18).** Store per-instance data in S3 with a SHA-256 manifest; mirror the public split to Hugging Face (300 GB per public dataset limit, [hosting](https://neurips.cc/Conferences/2026/EvaluationsDatasetsHosting)) and publish a sample under 4 GB for reviewers. To control egress cost, use S3 Requester Pays (requesters must authenticate, [docs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/RequesterPaysBuckets.html)) or apply to the AWS Open Data Sponsorship Program, which covers storage and sharing of qualifying public datasets ([program](https://aws.amazon.com/opendata/open-data-sponsorship-program/)). [AWS]
4. **Isolate the grader (3).** Run `mrab-grader` as a separate container with no network that receives only declared output artifacts. Never copy `tests/`, gold outputs or `solution/` into the agent image. Read large MRI arrays inside the grader container, since Inspect sandbox reads default to a 100 MB cap ([docs](https://inspect.aisi.org.uk/sandboxing.html)). [Docs/process; AWS for hosted runs]
5. **Gate every task change on oracle and null runs (4).** CI job per changed instance: `solve.sh` must score 1.0 (or its documented ceiling) five times in a row, an empty-output agent must score 0, and the score spread across repeats must stay within the stated tolerance (this catches KomaMRI CPU/GPU numerical drift). Light tasks on GitHub Actions; simulation-heavy tasks on AWS Batch, which runs container jobs on EC2 or Fargate ([docs](https://docs.aws.amazon.com/batch/latest/userguide/what-is-batch.html)). [CI, AWS]
6. **Define three tiers with different exposure rules (5, 6).** Public: data, graders and solutions (solutions encrypted). Semi-private: maintainers run API models only under zero-data-retention terms, as ARC does. Private: run only offline (open-weight models or submitted containers, no internet), as in ARC's Kaggle setup. Keep semi-private and private data in a separate AWS account and bucket that only maintainers can read. Write the rules in `docs/SPLITS.md`. [AWS, Docs/process]
7. **Start maintainer-run, then add an sb-cli-style service if demand appears (7, 8).** Phase 1: submitters send a container or agent code and maintainers run it (OSWorld, ARC, TB 4.0 model). Phase 2: a small API with email-verified keys and per-split quotas that queues AWS Batch grading jobs and writes results and logs to S3. [AWS]
8. **Publish a submission contract and validator (9, 10, 11).** `mragentbench-experiments` repo; each PR adds `metadata.yaml`, per-trial outputs, ATIF trajectories, `results.json`, token and dollar cost, and wall-clock. Require every instance, at least 3 trials (5 if affordable), default timeouts and resources, errored trials scored 0. A `verify` script regrades from the uploaded artifacts; a maintainer runs a trajectory judge for reward hacking; publish the disqualification policy. [Docs/process, CI]
9. **Mark and protect the data (12).** Generate an BlochBench canary GUID and place it in every `task.toml`, instruction, grader file and dataset card (LAB-Bench prefixes the BIG-bench GUID with its own tag). Gate the HF dataset with GAIA-style terms against crawlable resharing. Encrypt reference solutions and gold outputs in the public repo (gpg, as CORE-Bench does). Encrypt uploaded trajectories (HAL does this). [Docs/process]
10. **Write a per-family source blacklist and scan logs (14).** List the papers' code repositories, public datasets and known reproductions each task draws on; scan trajectories for those URLs, as PaperBench does, and score reward-hacked trials 0. [Docs/process, CI]
11. **Expert review of every instance (15).** At least two MRI researchers per instance check instruction clarity, grader correctness and solvability with a written rubric (SWE-bench Verified used three annotators per sample). Publish the rubric and annotations and record them in Croissant `rai:dataAnnotationProtocol` and `rai:annotationsPerItem`. [Docs/process]
12. **Make graders tolerant and auditable (16).** Use documented numeric tolerances (e.g. NRMSE or SSIM thresholds per family), return partial credit with sub-scores, and avoid LLM judges; if one is unavoidable, measure its agreement with human grades and publish judge accuracy and cost as PaperBench did. [Docs/process]
13. **Version tasks and keep artifacts for regrading (13).** Semantic version per task: patch (scores unaffected), minor (regrade stored artifacts), major (rerun), following Terminal-Bench. Keep `CHANGELOG.md` per family and store all run artifacts in S3 so minor grader fixes need no new agent runs. [AWS, Docs/process]
14. **Report like HAL and MLE-bench (10, 11).** Mean plus/minus standard error over trials, per family and overall, with cost, tokens and time; report a do-nothing baseline per family. [Docs/process]
15. **Scale with batch jobs and least privilege (17).** 88 instances times 5 trials is 440 trials per agent configuration; run them as AWS Batch array jobs, or through Harbor or Inspect providers. Give sandbox instances no IAM role or a minimal one: the Inspect EC2 sandbox warns that agents may be able to use the instance role ([repo](https://github.com/UKGovernmentBEIS/inspect_ec2_sandbox)). [AWS]
16. **Ship Croissant 1.1 plus RAI and a datasheet (18).** Include licence per task family (ScienceAgentBench kept original licences where needed), SHA-256 checksums, RAI fields for limitations, biases, personal or sensitive information (state how any human MRI data was de-identified and licensed), use cases, social impact, synthetic data, source datasets and provenance; validate with the Croissant validator before any NeurIPS E&D submission. [Docs/process]
17. **Publish completed ABC and BetterBench checklists (19).** Put them in `docs/checklists/` and update them each release. [Docs/process]
18. **Plan refresh and retirement (13, 19).** Each release, retire saturated or leaked tasks, move retired private tasks to public, and announce changes the way Terminal-Bench 4.0 did. [Docs/process]
