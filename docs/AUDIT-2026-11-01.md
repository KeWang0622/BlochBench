# Is BlochBench a legitimate benchmark? Audit of 1 November 2026

> Historical development note (1 November 2026). For current release status and evidence, use
> [the datasheet](../DATASHEET.md), [offline results](OFFLINE-RESULTS.md) and [roadmap](ROADMAP.md).

This audit checks BlochBench against published benchmark standards and against prior work, using the repository,
the study data and primary sources opened on 1 November 2026. It records what holds, what does not yet, and what must
change before v1.0.

> Historical audit. Current evaluation results and release status are in [OFFLINE-RESULTS.md](OFFLINE-RESULTS.md).
> Earlier experimental outcomes are not part of the current Core/Hard presentation.

## Verdict

BlochBench is a sound pre-release benchmark with an unusually strict grading design, and it fills a gap: no published
benchmark evaluates agents on end-to-end MRI research with physics-based grading. It is not yet a finished, citable
benchmark. Three gaps decide that: no external expert has reviewed any family yet, every result comes from a single agent
host, and the board covers only 24 instances, about half of whose families the strongest models already solve.

## What holds

| Criterion (source) | Evidence |
|---|---|
| Outcome validity: graders recompute results instead of trusting the agent (ABC I.f, I.g, I.h; [Zhu et al. 2025](https://arxiv.org/abs/2507.02825)) | Sequence replay in KomaMRI, reruns of submitted code on hidden data, voxelwise comparison with ground truth; no LLM judge |
| Trivial agents fail (ABC III.13) | An empty submission fails all 311 checks in all 24 families (docs/trivial-agent-grades.json) |
| Graders reject realistic mistakes (ABC I.d) | 196 negative controls; 191 of 195 with a declared target fail that check |
| Every task solvable (ABC II.7, II.8) | Reference solution passes every check of every instance |
| Data integrity | 88 packages, 6.69 GB; all 16,762 files match their frozen SHA-256 manifests (re-verified today) |
| Reproducible grading environment | Pinned grader image (Python 3.12.14, Julia 1.10.12, KomaMRI 0.14.0) built in CI; hosted grading reproduced the study's grades check for check on three development workspaces, including hidden-data reruns |
| Contamination controls by design (ABC III.3) | Canary GUID, hidden families and seeds, semi-private and private sets with hash commitments (docs/ROADMAP.md) |
| Statistics (BetterBench; [Reuel et al. 2024](https://arxiv.org/abs/2411.12990)) | Wilson intervals on the board; exact McNemar tests and cluster bootstrap in the study |
| Dataset documentation (NeurIPS 2026 E&D: [call](https://neurips.cc/Conferences/2026/CallForEvaluationsDatasets)) | croissant.json validates with mlcroissant 1.1.1 (only datePublished missing, to be set at release); licences: Apache-2.0 code, CC BY 4.0 data |
| Novelty | No benchmark of the same name on GitHub or arXiv; related work below covers radiology viewing, clinical workflows or single sequence tasks, not end-to-end MRI research |

## What does not hold yet

| Gap | Why it matters | Action before v1.0 |
|---|---|---|
| Expert review: 0 of 24 families reviewed (REVIEW.md status "pending" in every family) | Tasks were written by AI author agents; without expert review the tasks, tolerances and ground truth are unvalidated by the field (ABC I.d.1, II.6) | Run the review protocol with the 2-3 invited MRI researchers; publish reviews |
| One agent host (Codex CLI with every model) | Claude models were not run in Claude Code, so scores mix model and harness | Baselines in at least Claude Code and one open harness |
| Saturation: 11 of 24 families pass at 90% or more for the four strongest models without help | The board cannot separate frontier models on those families | Hard tier (docs/ROADMAP.md), recalibrate or retire saturated families |
| Small board: 24 instances, one per family | With one run per instance, 95% Wilson intervals on the current board are 14 to 37 percentage points wide | Grade all 88 public instances, three runs each |
| Run-to-run variation is not estimated by the current single-instance Core snapshot | Single runs do not establish reliability | Repeated-execution evaluation remains planned |
| Conflict of interest: the benchmark authors also build MRFoundry, developed on sibling instances of the same families | "+MRFoundry" entries are only clean on the sealed -r4 instances | Keep add-on comparisons to sealed and hidden instances; separate task and add-on authors (paper draft section 5) |
| Synthetic data only | External validity for real scanners and patients is untested | Add real-data families from redistributable sources (M4Raw CC BY 4.0, OpenNeuro CC0) |
| Negative-control coverage: 181 of 230 scientific checks | Sequence-design checks (hardware limits, raster, replay, readback) lack targeted negatives | Write the missing negatives |
| Grader determinism (ABC I.f.3) | Not yet measured on all workspaces | Historical follow-up; no new regrading is part of the offline snapshot update |
| Not public yet (ABC III.1, III.2) | Others cannot inspect or reproduce | Release only with the maintainer's explicit approval |
| Reference solutions in several layouts (reference_ws, refsol, reference_code) | Oracle runs cannot be automated uniformly | Standard solution/ folder per instance, oracle and empty runs in CI |

## Related work that the papers must cite

- Agent4MR (Zaiss et al., [arXiv:2604.13282](https://arxiv.org/abs/2604.13282), April 2026): an agent framework that
  generates and refines PyPulseq sequences with a physics-aware validation report, evaluated on a spin-echo EPI task
  against a context-only baseline (LLM4MR) and a human developer. Closest prior work to the sequence-design families,
  and to MRFoundry's idea of giving agents MR skills. Neither the MRFoundry manuscript nor the BlochBench draft cites
  it yet.
- ABRA ([arXiv:2605.11224](https://arxiv.org/abs/2605.11224)): 655 generated radiology-viewer tasks scored on planning,
  execution and outcome.
- HealthAgentBench ([arXiv:2606.31179](https://arxiv.org/abs/2606.31179)): 75 agentic healthcare tasks in 9 categories,
  binary success criteria.
- BCER Agent ([arXiv:2605.29163](https://arxiv.org/abs/2605.29163)): long-horizon MRI analysis workflows on brain,
  prostate and cardiac tasks.
- FedAgentBench ([arXiv:2509.23803](https://arxiv.org/abs/2509.23803)) and VERITAS
  ([arXiv:2604.12144](https://arxiv.org/abs/2604.12144)): agents for federated medical-image analysis and for
  image-derived hypothesis testing.

None of these grades MRI research outputs by re-simulation and hidden-data reruns across acquisition, reconstruction,
quantification, statistics and writing, which is BlochBench's distinct contribution.

## Practices from other benchmarks still to adopt

From docs/LANDSCAPE.md: maintainer-run verification as Terminal-Bench 4.0 and OSWorld-Verified do, trajectory review for
reward hacking, a standard task folder with an oracle solution, at least three trials with errors counted as failures,
and a published retirement policy.
